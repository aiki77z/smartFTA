## 阶段 9：校验、重建、经验优化路由修正

完成时间：2026-08-15

### 已完成

- 将 v2 LangGraph 主链路调整为：
  `SupervisorAgent -> RetrievalAgent -> TreeDraftAgent -> VerifyAgent`
  - 若校验失败：返回 `TreeDraftAgent` 重新构建草稿，最多重建 3 次。
  - 若校验成功且尚未优化：进入 `RepairAgent`，此处业务语义为“基于 Experience Memory 的优化智能体”。
  - 若优化产生新草稿：返回 `VerifyAgent` 再校验一次。
  - 若优化未产生结构性修改：沿用已通过校验的草稿并进入 `CommitAgent`。
  - 若优化后的草稿再次校验通过：进入 `CommitAgent`。
  - 若重建 3 次后仍未通过：进入人工复核。
- 新增草稿重建上限配置，把失败后的循环上限从“修复次数”语义调整为“草稿重建次数”语义；该阈值已在阶段 10 调整为 `MAX_DRAFT_REBUILD_ATTEMPTS = 2`。

## 阶段 22：人工复核草稿提交入库修复

完成时间：2026-08-15

### 已完成

- 修复人工复核草稿加载到画布后无法保存的问题。

  - 可关联原始 `agent_run`，回写 `tree_id/tree_version`；
  - 不对 AI 草稿执行阻断式结构校验，因为人工复核路径本身可能来自校验失败草稿。
- 前端新增 `reviewDraftContext`：
  - 加载待复核草稿时记录原始草稿、runId、顶事件信息和选中文件版本范围；

## 阶段 23：人工复核草稿保存修复后的前端白屏修正

- 同时简化人工复核草稿保存兜底判断：
