# generate-fta 数据库和参数简要说明

本文只保留运行 `generate-fta` 后端时最常用的数据库与参数说明。具体取值以项目根目录下的 `.env` 和 `config.py` 为准，密钥类参数不要提交到 Git。

## 一、数据库

后端主要使用 MongoDB 保存业务数据，使用 Neo4j 保存知识图谱关系。

### MongoDB

连接参数：

- `MONGO_URI`：MongoDB 连接地址，默认 `mongodb://localhost:27017/`
- `MONGO_DB_NAME`：数据库名，默认 `fault-tree-trial`

主要集合：

- `files`：文件级信息，保存文件名、规范化文件名等。
- `file_versions`：知识库文件版本，核心字段包括 `file_id`、`file_version_id`、`version_no`、`is_active`、`status`。系统按活跃版本选择知识库范围。
- `chunks`：文档分块内容，核心字段包括 `chunk_id`、`chunk_uid`、`file_id`、`file_version_id`、`is_active`。`chunk_uid` 通常由 `file_version_id::chunk_id` 组成。
- `entity_reverse_index`：实体到分块的反向索引，用于从故障部件、故障现象等实体召回原文证据。
- `top_event_catalog`：顶事件目录，按 `file_version_id` 维护可生成的顶事件候选，并可保存语义向量。
- `fault_trees`：当前故障树主记录。
- `fault_tree_versions`：故障树历史版本，用于保存、回滚和查看修改历史。
- `generation_jobs`、`generation_job_items`：批量生成任务及每个顶事件的执行状态。

### Neo4j

连接参数：

- `NEO4J_URI`：Neo4j Bolt 地址，默认 `bolt://localhost:7687`
- `NEO4J_USER`：用户名，默认 `neo4j`
- `NEO4J_PASSWORD`：密码；为空时图谱检索不可用
- `NEO4J_DATABASE`：数据库名，默认 `neo4j`

Neo4j 中保存知识图谱节点和关系。导入知识库产物时，节点、边都会带 `file_id`、`file_version_id`、`file_name` 等属性。生成故障树时，后端会按 `selected_file_version_ids` 限定检索范围，避免不同版本知识库混用。

## 二、重要运行参数

### 大模型参数

- `LLM_API_KEY`：大模型 API Key。
- `LLM_BASE_URL`：大模型接口地址，默认 `https://api.deepseek.com`。
- `LLM_MODEL`：生成与解析使用的模型，默认 `deepseek-chat`。
- `LLM_PARSE_MAX_TOKENS`：顶事件解析等短任务 token 上限，默认 `300`。
- `LLM_GENERATION_MAX_TOKENS`：故障树生成 token 上限，默认 `16384`。
- `LLM_REPAIR_MAX_TOKENS`：修复/改写 token 上限，默认 `16384`。
- `LLM_VALIDATION_MAX_TOKENS`：校验任务 token 上限，默认 `4096`。

### 向量与语义召回参数

- `EMBEDDING_API_KEY`：向量模型 API Key；不配置时默认复用 `LLM_API_KEY`。
- `EMBEDDING_BASE_URL`：向量模型接口地址；不配置时默认复用 `LLM_BASE_URL`。
- `EMBEDDING_MODEL`：向量模型名；为空时语义召回会退化为名称匹配。
- `EMBEDDING_BATCH_SIZE`：批量向量化大小，默认 `10`。
- `SEMANTIC_SIMILARITY_THRESHOLD`：语义匹配阈值，默认 `0.72`。

### 图谱生成与检索参数

- `ENABLE_GRAPH_RETRIEVAL`：是否启用图谱召回，默认 `false`。
- `ENABLE_GRAPH_TREE_BUILDING`：是否启用基于图谱的故障树构建，默认 `true`。
- `GRAPH_TREE_MAX_DEPTH`：图谱扩展最大深度，默认 `3`。
- `GRAPH_TREE_MAX_NODES`：图谱扩展最大节点数，默认 `30`。

## 三、常用接口参数

- `selected_file_version_ids`：前端或接口传入的知识库版本范围。为空时通常使用当前活跃版本。
- `candidate_limit`：顶事件候选数量，生成前解析顶事件时使用。
- `confirmed_top_event` / `confirmed_normalized_top_event` / `confirmed_graph_node_id`：前端确认顶事件后传回，减少模型二次判断。
- `sync`：`/api/tree/generate` 是否同步等待生成完成；`false` 时返回任务 ID 供轮询。
- `chunks_file`、`entities_file`、`relations_file`：`/api/integration/import-knowledge-artifacts` 导入知识库产物时使用的文件路径。
- `file_id`、`file_name`、`file_version_id`：导入知识库时可显式指定文件和版本标识；不指定时后端自动派生。
- `chunks_import_mode`：分块导入模式，支持 `replace` 或 `append`。
- `clear_graph`：版本化知识库模式下禁止清空全图，应保持 `false`。

## 四、基本流程

1. 在 `.env` 中配置 MongoDB、Neo4j、大模型和向量模型参数。
2. 通过 `/api/integration/import-knowledge-artifacts` 导入 chunks、实体索引和关系文件。
3. 后端写入 MongoDB，必要时同步关系到 Neo4j，并为该 `file_version_id` 重建 `top_event_catalog`。
4. 前端选择知识库文件版本，接口通过 `selected_file_version_ids` 控制召回范围。
5. 调用 `/api/tree/resolve-top-event` 解析顶事件，再调用 `/api/tree/generate` 或 `/api/batch/generate-all` 生成故障树。
