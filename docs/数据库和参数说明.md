# generate-fta 数据库和参数简要说明

本文只说明 `generate-fta` 生成服务运行时需要读取和写入的数据。知识库构建、文件版本管理、chunks/entity/relation 导入由 `kb-v2` 服务负责，`generate-fta` 不再提供知识库导入接口。

## 一、数据库

### MongoDB

连接参数：

- `MONGO_URI`：MongoDB 连接地址，默认 `mongodb://localhost:27017/`
- `MONGO_DB_NAME`：数据库名，默认 `fault-tree-trial`

`generate-fta` 读取这些知识库集合：

- `files`、`file_versions`：由 KB 服务维护，GNR 用它们解析 `selected_file_version_ids` 和活跃版本范围。
- `chunks`：由 KB 服务维护，GNR 用于证据召回和生成依据；实体到 chunk 的引用从 Neo4j 节点读取。
- `top_event_catalog`：由 KB 服务维护，GNR 用于顶事件解析、候选确认和批量生成入口。

`generate-fta` 写入这些生成结果集合：

- `fault_trees`：当前故障树主记录。
- `fault_tree_versions`：故障树历史版本，用于保存、回滚和查看修改历史。
- `generation_jobs`、`generation_job_items`：批量生成任务及每个顶事件的执行状态。

### Neo4j

连接参数：

- `NEO4J_URI`：Neo4j Bolt 地址，默认 `bolt://localhost:7687`
- `NEO4J_USER`：用户名，默认 `neo4j`
- `NEO4J_PASSWORD`：密码；为空时图谱检索不可用
- `NEO4J_DATABASE`：数据库名，默认 `neo4j`

Neo4j 图谱由 KB 服务导入和维护。GNR 生成故障树时按 `selected_file_version_ids` 限定节点和关系的 `file_version_id`，避免不同版本知识混用。

## 二、重要运行参数

- `LLM_API_KEY`：大模型 API Key。
- `LLM_BASE_URL`：大模型接口地址，默认 `https://api.deepseek.com`。
- `LLM_MODEL`：生成与解析使用的模型，默认 `deepseek-chat`。
- `LLM_PARSE_MAX_TOKENS`：顶事件解析等短任务 token 上限，默认 `300`。
- `LLM_GENERATION_MAX_TOKENS`：故障树生成 token 上限，默认 `16384`。
- `LLM_REPAIR_MAX_TOKENS`：修复/改写 token 上限，默认 `16384`。
- `LLM_VALIDATION_MAX_TOKENS`：校验任务 token 上限，默认 `4096`。
- `EMBEDDING_MODEL`：向量模型名；为空时语义召回会退化为名称匹配。
- `SEMANTIC_SIMILARITY_THRESHOLD`：语义匹配阈值，默认 `0.72`。
- `ENABLE_GRAPH_RETRIEVAL`：是否启用图谱召回，默认 `false`。
- `ENABLE_GRAPH_TREE_BUILDING`：是否启用基于图谱的故障树构建，默认 `true`。
- `GRAPH_TREE_MAX_DEPTH`：图谱扩展最大深度，默认 `3`。
- `GRAPH_TREE_MAX_NODES`：图谱扩展最大节点数，默认 `30`。

## 三、常用接口参数

- `selected_file_version_ids`：前端或接口传入的知识库版本范围。为空时使用当前活跃版本。
- `candidate_limit`：顶事件候选数量，生成前解析顶事件时使用。
- `confirmed_top_event` / `confirmed_normalized_top_event` / `confirmed_graph_node_id`：前端确认顶事件后传回，减少模型二次判断。
- `sync`：`/api/tree/generate` 是否同步等待生成完成；`false` 时返回任务 ID 供轮询。

## 四、基本流程

1. 启动 MongoDB、Neo4j、`kb-v2` 和 `generate-fta`。
2. 通过 `kb-v2` 构建或导入知识库，写入版本化 chunks、实体索引、Neo4j 关系和 `top_event_catalog`。
3. 前端选择知识库文件版本，接口通过 `selected_file_version_ids` 控制召回范围。
4. 调用 `/api/tree/resolve-top-event` 解析顶事件。
5. 调用 `/api/tree/generate` 或 `/api/batch/generate-all` 生成故障树。
